## 「画像はもう別のところで作ったんです。」

ナレーションの録音も終わり、SRT のタイミングも合わせ、シーンも CSV でグループ化しました。でも画像は AutoFlowCut の中で生成していません — Midjourney、DALL·E、Stable Diffusion など、いつも使っているお気に入りのツールで作りました。そして今、`0001.png`、`0002.png`、`0003.png` でいっぱいのフォルダを眺めながら、こう考えています:

> 「この画像を AutoFlowCut に入れて、それぞれ正しいシーンに配置するにはどうすれば？SRT とナレーションのタイミングは崩さずに。」

朗報です。プロジェクトファイルを編集する必要も、プラグインを入れる必要もありません。AutoFlowCut は **画像のファイル名こそが画像とシーンを結びつける鍵**になるよう設計されています。名前を正しく揃えて一つのフォルダに入れ、開き直すだけ — 完了です。SRT とナレーションのタイミングは別に保存されているので、一切触れられません。

具体的にどう動くのか見ていきましょう。

## たった一つのルール: ファイル名がすべてを決める

AutoFlowCut は `project.json` 内のパスを信頼できる情報源とは**しません**。プロジェクトを開くたびに、アプリは **`scenes/` フォルダを再スキャン**し、各ファイルを名前でシーンにマッチさせます。

つまり、自分の画像を紐づける確実な方法はシンプルです:

**各画像をシーン ID に合わせてリネームし、プロジェクトの `scenes/` フォルダに入れる。**

JSON の編集は不要です。`project.json` に画像パスを手で書き込んでも、アプリは次回のロード時に上書きしてしまいます — なので無駄です。ファイル名こそが契約です。

## プロジェクトはどこに保存される？

各プロジェクトは単一のファイルではなく、**フォルダ**です。場所は次のとおりです:

```
Windows:  C:\Users\<ユーザー>\Documents\AutoFlowCut\<プロジェクト名>\
macOS:    ~/Documents/AutoFlowCut/<プロジェクト名>/
```

(アプリ内で作業フォルダを自分で指定した場合は、その下にあります。)

フォルダ内部の構造はこうなっています:

```
<プロジェクト名>\
    ├── project.json     ← シーン、プロンプト、SRT トラック、ナレーションのタイミング
    ├── scenes\          ← 画像はここに入れます
    ├── references\
    ├── videos\
    └── sfx\
```

シーン ↔ 画像のマッチングを実際に制御するのは `project.json` のフィールド**ではなく**、`scenes\` フォルダ内の各ファイルの**ファイル名**です。

## 命名ルール（みんなが一番間違えるところ）

AutoFlowCut のシーン ID はこうです:

```
scene_1, scene_2, scene_3, ...
```

**1 から始まり、ゼロ埋めはしません。** そのためアプリが探すファイルは:

```
scenes/scene_1.png
scenes/scene_2.png
scenes/scene_3.png
```

書き出したファイルはおそらく `0001.png`、`0002.png`、… という名前でしょう — これは**マッチしません**。必ずリネームする必要があります:

| 自分のファイル | リネーム後      |
|----------------|----------------|
| `0001.png`     | `scene_1.png`  |
| `0002.png`     | `scene_2.png`  |
| `0003.png`     | `scene_3.png`  |

**拡張子の優先順位:** シーンに既存のファイルがある場合、アプリは次の順で最初にマッチしたものを選びます — `png → jpg → jpeg → webp → gif → mp4 → webm`。古い画像が選ばれるのを防ぐには、すべて `.png` に統一するか、そのシーンの既存ファイルを先に削除してください。

## ステップバイステップ

1. プロジェクトフォルダを開きます（例: `…\Documents\AutoFlowCut\my-project\`）。
2. 画像をシーン ID のパターンにリネームします — `scene_1.png`、`scene_2.png`、…（**`0001.png` ではありません**）。
3. **`scenes\`** サブフォルダにコピーします。
4. AutoFlowCut でプロジェクトを開き直します。アプリが `scenes/scene_N.*` をスキャンし、各画像をシーンに自動で紐づけ、「完了」状態にします。

これで終わりです。SRT の各行とナレーションのタイミングはそのまま維持されます。

## 一つ確認すること: グループ CSV でのシーン順序

グループ化されたシーン CSV をインポートすると、AutoFlowCut はシーン ID をインポート順に**連番で割り当てます** — `scene_1`、`scene_2`、`scene_3`、… — これは **CSV の `scene` 番号カラムとは無関係**です。

- CSV のシーン番号がすでに `1, 2, 3…` の順なら、すべてぴったり合います。
- 番号が飛んでいたり順序が入れ替わっている場合は、画像の番号を CSV の元の番号ではなく、**アプリ画面に表示されるシーン順**に合わせてください。

手早い確認法: AutoFlowCut で最初のシーンを開き、`scene_1.png` が入るべきシーンで合っているか目で確認しましょう。

## リネームは GPT や Claude に任せましょう

これは AI アシスタントに任せるのにうってつけの作業です。プロジェクトファイルを編集させる（どうせ上書きされます）のではなく、ファイルの**リネームスクリプトを作らせて**ください:

> 「`0001.png` から `0240.png` までのファイルがある。これを `scene_1.png` から `scene_240.png` にリネームするスクリプトを書いて（1 始まり、ゼロ埋めなし）。」

スクリプトを実行し、結果を `scenes\` に入れて開き直すだけ。AI が本当に時間を節約してくれるのはまさにこの部分です。

## 動画はどうすれば？

ここでは AutoFlowCut が現在どう動作するかを正直にお伝えするのが大切です。

**AutoFlowCut は現在、自分の動画ファイルをシーンにインポートする機能をサポートしていません。** UI に「動画を添付」という選択肢はありません — アプリはシーン動画が自身の生成ステップで作られ、内部 ID（`t2v_5.mp4` / `i2v_5.mp4` など）で `videos\` フォルダに保存されることを前提としています。画像と違い、動画ファイルはディスクから一括スキャンされ**ない**ため、フォルダに `.mp4` を入れるだけではシーンに紐づきません。

外部ツール（Sora、Kling、Runway など）のクリップを使いたい場合、現実的な手順はこうです:

1. 上記の方法で **画像**を AutoFlowCut に入れます。
2. プロジェクトを **CapCut** または **Premiere** に書き出します。
3. エディタで、目的のシーンの静止画を外部の動画クリップに差し替えます。タイムラインはすでに SRT のタイミングに合わせて作られているので、メディアを入れ替えるだけ — タイミングと字幕はそのまま維持されます。

こうすればワークフローがすっきりと保たれ、アプリが設計上想定していない方法と格闘せずに済みます。

## 一行まとめ

**シーン ↔ 画像のマッチングの信頼できる情報源は、プロジェクトファイルではなく、プロジェクトの `scenes/` フォルダ内のファイル名 `scene_<N>.<拡張子>` です。** 画像を `scene_1.png`、`scene_2.png`、… と名付けて `scenes\` に入れ、開き直せば、すべての画像が正しいシーンに配置され、SRT とナレーションのタイミングは完璧にそのまま維持されます。
