# 드라마 블로그 — 설계 (2026-10-28)

> 배포 경로 주의: 이 리포의 `docs/` 는 배포되지 않는 옛 사본이다. 사이트 소스는 `landing/` 뿐이다.
> 이 문서만 설계 기록으로 여기 둔다.

## 왜

touchizen.com 블로그(`/{lang}/blog/`)에는 IT·AutoFlowCut 글만 있다. 사용자는 유튜브 채널
**고든인사이트**(`UCF79bfcre5z5WZmN8ncsA2Q`)에 드라마 해석 롱폼을 매일 올리고 있고, 그 대본을
글로 바꿔 사이트에 올리고 싶어 한다. 노리는 것은 둘이다.

1. **유튜브 조회수** — 글 안에 영상을 임베드해서, 검색으로 글에 온 사람이 영상을 보게 한다
   (임베드 재생도 조회수로 잡힌다).
2. **애드센스 수익** — 2026-10-28 사이트 전체에 자동 광고를 붙였다(`landing/lib/adsense.test.ts`).
   읽는 사람이 페이지에 머무를수록 광고가 보인다. 그래서 "링크만 걸기"가 아니라 임베드다.

별도 리포·서브도메인이 아니라 **같은 사이트 안에 블로그를 하나 더** 둔다(사용자 결정). 도메인
신뢰도·애드센스·ads.txt·GA 가 그대로 따라온다.

## 목표

- 블로그를 **카테고리 여러 개**로 운영하는 틀을 만든다: 지금 IT·AI(기존), 이번에 드라마, 나중에
  경제. 메인에서는 헤더의 "블로그" 하나로 들어가 카테고리로 갈라진다(사용자와 합의한 구조).
- `/{lang}/blog/drama/` 에 드라마 블로그를 연다. 4개 언어(ko·en·ja·de) — 사용자 결정.
- 첫 묶음: 「100일의 거짓말」 롱폼 중 **유튜브에 올라간 4편 → 글 4편 × 4개 언어 = 16개 파일**.
  7화 상상 시나리오(5번째 영상)는 사용자가 "당장 안 해도 돼, 배포 후에 게시돼도 상관없어" — 첫 배포 뒤
  같은 틀로 따로 올린다(아래 표에 남겨 둔다).
- 글마다 맨 위에 그 영상 임베드, 끝에 "유튜브에서 보기"·"채널 구독" 링크.
- 드라마가 늘어나도(다음은 「닥터X」, 사용자가 100일 끝나면 원본을 준다) 콘텐츠 폴더에 파일만
  더하면 되는 구조.

## 목표가 아닌 것 (이번엔 안 함)

- 닥터X 글 — 구조만 준비. 원본이 아직 없다.
- 1화 리뷰(`100days-ep1`) — 유튜브에 안 올렸다(사용자가 1~2화 리뷰를 접었다). 임베드할 영상이 없다.
- 드라마별 시리즈 전용 페이지, 댓글, RSS.
- 드라마 영상 스킬(drama-preview/weekday/prediction-video)에 "업로드 뒤 블로그 글 쓰기" 단계를
  넣는 일 — 이번 묶음이 자리 잡은 뒤 따로 정한다.
- 스페인어(es) — 썸네일·자막엔 es 가 있지만 사이트 언어는 4개다.
- 경제 블로그 — 틀만 받쳐 주고 글은 없다(빈 카테고리는 숨으니 아무것도 안 보인다).
- 쇼핑 블로그 — 안 만든다. 사용자: "쇼핑은 당분간 쇼츠만".

## 실패로 치는 것 (돌아가더라도)

- 기존 `/{lang}/blog/...` 주소가 바뀌거나, 드라마 글이 IT 블로그 목록에 섞이는 것.
- **스틸컷 남발·대사 장문 전사** — 저작권 이미지·텍스트가 많으면 애드센스가 승인을 거절하거나
  광고를 제한한다. 사용자 결정: 스틸 최소.
- 대본 표를 그대로 붙인 글(화면 지시·타임코드·"(클립)" 이 남은 글) — 얇은 콘텐츠로 본다.
- 언어마다 인물 이름 표기가 다른 것(Ga-kyung / Gakyung 섞임).
- 영상보다 더 스포하는 글. 글은 영상과 같은 범위만 다룬다.

## 단계 (사용자 2026-10-28: "오늘은 블로그 틀을 만들고 배포시키는 게 중요")

1. **1단계 — 틀 (오늘 배포)**: 카테고리 구조, 허브 `/{lang}/blog/`, IT 목록 `/{lang}/blog/tech/`,
   헤더·푸터, 카테고리별 sitemap 과 자동 색인. 이때 카테고리 목록에는 **IT 하나만** 있다.
2. **2단계 — 드라마 열기 + 글**: 드라마 카테고리(목록 한 줄 + 라우트 + sitemap 라우트)를 **첫 드라마 글과
   같은 커밋으로** 연다. 그다음 글 4편 × 4개 언어.

드라마를 1단계에 미리 열지 않는 이유: 정적 export 는 글이 0개인 동적 라우트를 그대로 못 만든다
(`generateStaticParams` 가 비면 빌드가 막혀, 기존 블로그도 `_placeholder` 페이지로 피해 간다). 빈
`/blog/drama/` 나 자리표시 페이지가 생기면 "빈 카테고리는 어디에도 안 나온다" 가 깨진다. 그래서
**카테고리 목록에는 글이 있는 카테고리만 들어간다** — 이게 숨김 규칙을 구조로 보장한다(테스트로 강제:
목록의 모든 카테고리는 4개 언어 모두에 글이 있다).

## 내가 정한 것 (사용자 확인 전 판단)

### 카테고리와 주소 (`trailingSlash: true`)

| 화면 | 주소 | 비고 |
|---|---|---|
| 블로그 첫 화면 | `/{lang}/blog/` | 지금은 IT 목록 → **카테고리 허브**로 바뀐다 |
| IT·AI 목록 | `/{lang}/blog/tech/` | 새 주소 |
| IT·AI 글 | `/{lang}/blog/{slug}/` | **기존 주소 그대로** — 색인·공유 링크 보호 |
| 드라마 목록 | `/{lang}/blog/drama/` | |
| 드라마 글 | `/{lang}/blog/drama/{slug}/` | |
| (나중) 경제 | `/{lang}/blog/economy/`, `/{lang}/blog/economy/{slug}/` | 이번엔 글 없음 |

- 카테고리 id(`tech`·`drama`·`economy`)는 IT 글 slug 와 겹치면 안 된다(정적 세그먼트가 `[slug]` 를
  가린다) — 테스트로 막는다.
- **글이 하나도 없는 카테고리는 어디에도 안 나온다**(헤더·허브·푸터·sitemap). 빈 페이지는 애드센스가
  가치 없는 콘텐츠로 본다. 첫 글이 들어가면 저절로 나타난다.
- 콘텐츠: IT 는 지금 그대로 `landing/content/blog/{lang}/`, 드라마는 `landing/content/drama/{lang}/{slug}.md`
  (경제는 `content/economy/`). 같은 slug 가 네 언어에 다 있어야 한다.

### 메인에서 들어가는 길
- **헤더**: 메뉴는 그대로 "제품 · 특징 · 블로그 · 제휴 프로그램". "블로그"는 누르면 허브로 가고,
  데스크톱에선 올리면, 모바일 메뉴에선 펼치면 글이 있는 카테고리가 보인다(카테고리가 2개 이상일 때만 —
  하나뿐이면 하위 메뉴 없이 허브 링크만). 카테고리마다 헤더 항목을
  따로 두지 않는다(4개 언어, 특히 독일어에서 넘친다).
- **허브** `/{lang}/blog/`: 카테고리마다 소제목 + 최신 글 3개 + "더 보기 →"(그 카테고리 목록).
  카테고리가 하나뿐일 때(1단계)는 그 카테고리 글 전부 — 지금 블로그 목록보다 나빠지지 않게.
  모든 글을 최신순으로 섞지 않는다 — 드라마가 매일 올라와 IT 글이 묻힌다.
- **푸터**: 글이 있는 카테고리 링크.
- 메인 화면 본문에는 블로그를 넣지 않는다(제품 소개 페이지라 드라마 글이 섞이면 메시지가 흐려진다).
- 글 화면의 "돌아가기"·이전/다음·관련 글은 **같은 카테고리 안에서만**.
- slug 는 영어 kebab: `100-days-of-deception-ep7-preview`, `100-days-of-deception-gyeam-ri-13-years-ago`,
  `100-days-of-deception-hideo-sato-family-past`, `100-days-of-deception-shanghai-housekeeper`,
  `100-days-of-deception-ep7-imagined-scenario`. 작품 영어명은 넷플릭스 제목 *100 Days of Deception*.

### front matter (블로그 글과 같은 키 + 셋)
기존 키(`title`·`date`·`excerpt`·`tags`·`author`·`image`·`noindex`·`modified`)에 더해:
- `youtube`: 영상 ID (필수, 11자)
- `series`: 화면에 보일 작품명. ko 「100일의 거짓말」, en·de *100 Days of Deception*, ja 는
  유튜브 일본어 제목과 같은 "100 Days of Deception（100日の嘘）"(일본 현지 제목은 확인 안 됨 —
  `100days-wk-1027/youtube-meta-langs.md`). 그 언어 글 안에서 통일.
- `seriesId`: 언어와 무관한 묶음 키(`100days`, 나중에 `doctorx`)

### 코드
- `landing/lib/blog.ts` 를 "어느 카테고리인지(`tech` | `drama` | `economy`)" 를 받게 일반화한다 —
  콘텐츠 폴더와 주소 앞부분만 다르다. **IT 글의 주소·메타·JSON-LD·sitemap 출력은 그대로**여야 하고,
  기존 테스트(`blog-*.test.ts`)는 고치지 않고 통과해야 한다(예외: 아래 sitemap 색인 검사 하나). 카테고리 목록(id·폴더·주소·문구 키)은
  한 곳에 둔다.
- 라우트는 카테고리마다 **실제 폴더**(`blog/tech/`, `blog/drama/`, `blog/drama/[slug]/`)를 두고, 각
  `page.tsx` 는 공용 컴포넌트를 부르는 얇은 파일이다. Next 14 는 `blog/[slug]` 옆에 `blog/[category]`
  를 둘 수 없어서다. 그래서 경제를 열 때는 카테고리 목록 한 줄 + `content/economy/` + 얇은 라우트 파일
  두 개(드라마 것 복사)를 더한다. **지금은 `economy/` 라우트 폴더를 만들지 않는다**(만들면 빈
  `/blog/economy/` 페이지가 빌드된다).
- 목록·글 화면은 기존 `BlogPageClient`·`BlogPostClient` 를 재사용한다(주소 앞부분·문구를 받게).
  드라마 목록은 **작품별 묶음**(작품명 소제목 아래 최신순).
- 언어 전환(헤더의 `onLanguageChange`)은 같은 카테고리·같은 글로 간다.
- 글 화면: `youtube` 가 있으면 제목·메타 바로 아래 16:9 임베드(`https://www.youtube.com/embed/{id}`,
  `title` 속성 = 글 제목), 본문 끝에 "유튜브에서 보기"(`https://youtu.be/{id}`) ·
  "고든인사이트 구독"(`https://www.youtube.com/channel/UCF79bfcre5z5WZmN8ncsA2Q?sub_confirmation=1`).
- JSON-LD: 기존 `BlogPosting` 에 `video`(`VideoObject`: name·description·thumbnailUrl
  `https://i.ytimg.com/vi/{id}/maxresdefault.jpg`·uploadDate·embedUrl)를 더한다 — 영상 검색 노출용.
- sitemap: **카테고리마다 따로**(사용자 지적 — 서치 콘솔에서 sitemap 별로 색인 현황을 나눠 본다).

  ```
  sitemap.xml (색인 — robots.txt 가 가리킨다, 빌드 때 자동 생성)
   ├ sitemap-pages.xml   손으로 쓴 페이지(그대로)
   ├ sitemap-blog.xml    IT 글 — 이름 그대로(이미 서치 콘솔에 등록돼 있다)
   ├ sitemap-drama.xml   드라마 글 — 새로, 빌드 때 content/drama 에서 생성
   └ (나중) sitemap-economy.xml
  ```

  - 카테고리 sitemap 생성은 지금 `sitemap-blog.xml` 과 같은 방식(`app/sitemap-<이름>.xml/route.ts` 가
    공용 함수를 카테고리를 넘겨 부른다). IT 쪽 `sitemap-blog.xml` 출력은 그대로.
  - **색인 `sitemap.xml` 도 자동 생성**(사용자: "블로그는 많아질 거") — `app/sitemap.xml/route.ts` 가
    `sitemap-pages.xml` + 카테고리 목록의 sitemap 파일을 차례로 낸다. `public/sitemap.xml` 은 지운다(같은
    경로를 두 곳에서 만들면 충돌). 카테고리를 열면 색인에 저절로 들어간다.
  - `lib/blog-sitemap.test.ts` 의 "색인 = 정확히 [pages, blog]" 검사는 지금 상태를 못 박은 것이라
    **"색인 = pages + 카테고리마다 하나"** 로, 읽는 곳도 `public/sitemap.xml` → 색인 라우트로 고친다(이
    테스트만 예외로 고친다 — 나머지 기존 테스트는 그대로 통과).
  - 카테고리 목록 페이지(`/blog/tech/` 등)는 sitemap 에 넣지 않는다 — 헤더·허브에서 링크되고,
    `sitemap-pages.xml` 은 `/blog/x/` 꼴을 금지하며, 글 sitemap 은 글만 담는 꼴이라 그대로 둔다.
- 카테고리 이름: IT·AI = "IT·AI"(ko) / "Tech & AI"(en) / "IT・AI"(ja) / "Tech & KI"(de),
  드라마 = "드라마" / "Drama" / "ドラマ" / "Drama", 경제 = "경제" / "Economy" / "経済" / "Wirtschaft".
- i18n 문구는 `landing/lib/i18n/{ko,en,ja,de}.ts` 네 파일에 **같은 줄 위치로** 추가(네 파일이
  line-parallel 이다).
- 새 화면은 전부 `app/(main)/[lang]/blog/` 아래라 `lib/products.test.ts`(이미 `blog` 를
  `NOT_ON_MAIN_PAGE` 에 둠)에 새 항목이 생기지 않는다.

### 글 쓰는 법 (ko 원본)
- 영상의 흐름을 그대로 따른다: ⚠️ 스포 범위 안내(설명란의 ⚠️ 줄) → 도입(그 편의 "질문 하나") →
  **챕터 = H2**(`youtube-meta.md` 의 📌 챕터 이름, '오프닝'은 도입으로 흡수) → 오늘의 답 →
  고든인사이트 픽 → 출처(설명란 📰 실제 역사 출처) → 유튜브 링크.
- 말투는 영상 내레이션의 말투(친근한 "~요")를 살리되 **읽는 글로** 고친다: 화면 지시, `@분:초`,
  `🔊` 구간, "(클립)", "(원음)", "여러분 보셨죠?" 같은 말로 하는 군더더기는 뺀다.
- **대사 인용은 글마다 10개 이하**, 하나는 자막 한 줄(🔊 한 구간) 이하, 대사 합계는 본문의 10% 이하
  (내 판단). 원본 대본은 대사 인용이 37~72개라 대부분은 내레이션 안에서 풀어 쓴다. 남기는 10개는
  그 글의 질문·답·픽을 받치는 핵심 대사다. 내레이션이 문장 중간에 대사로 넘어가는 줄
  (`… → 🔊`)은 풀어 쓰거나 짧은 인용 하나로 바꾼다. 우리 해석이 주, 인용이 종이어야 한다(저작권법
  정당한 인용의 주종관계).
- "제 추리"·"픽"·"뇌피셜" 표시는 영상처럼 그대로 둔다(해석과 사실을 구분하는 장치다).
- 분량은 **내레이션을 줄이지 않는 쪽이 우선**이다(따로 글자 수 범위를 두지 않는다 — 내레이션만
  공백 빼고 4,600~5,000자 남짓이다). 늘리려고 새 주장을 지어내지 않는다 — 대본·`youtube-meta.md`·
  폴더의 `research/` 에 있는 것만 쓴다.

### 스틸컷
- 글마다 **2~3장**. `스틸★` 은 대본 거의 모든 줄에 붙어 있어 고를 범위를 좁혀 주지 않는다 —
  그 글의 **질문·답·픽을 받치는 장면**을 고른다. 드라마 본편 장면을 우선한다.
- **원본 녹화본에서 직접 뽑는다**: 대본 `화면` 칸의 `[epN]`(없으면 그 폴더 `config.json` 의
  `recording`)과 `@분:초` → `config.json` 의 `sources[epN]`/`recording` 경로(2026-10-28 다섯 폴더 모두
  파일 있음)에서 ffmpeg 로 그 시각 프레임. `snap/` 은 완성 영상 프레임이라 자막·배지가 박혀 있어
  쓰지 않는다(1026 엔 아예 없다). 뽑은 프레임은 눈으로 확인한다(어두운 컷·전환 중 프레임이면 ±1초).
- 가로 1280px 이하, 장당 200KB 이하 JPEG/WebP 로 줄여 `landing/public/images/drama/100days/{slug}/`.
  같은 이미지를 네 언어가 함께 쓴다.
- **캡션은 출처별**로 단다: 드라마 본편·tvN 공식 예고·클립 = "ⓒ tvN 「100일의 거짓말」"(언어별),
  다큐·뉴스 자료 화면 = 그 방송사와 프로그램명(설명란 🎬 자료 화면 목록 기준), 퍼블릭 도메인 사진 =
  그렇다고 밝힌다. 일괄 "ⓒ tvN" 금지.
- OG 이미지(`image`)는 영상 썸네일: 언어별 `thumbnail_{lang}.jpg` 가 있으면 그것, 없으면 `thumbnail.jpg`
  — 같은 폴더에 줄여서 둔다(`thumb-{lang}.jpg`). 썸네일은 목록 카드 이미지도 겸한다.

- 이름 표기는 `100days-wk-1028b/youtube-meta-langs.md` 머리말의 표기(Ga-kyung, Hideo, So-ran,
  Yoo Philip, Sato Shinichi, Fukuda, Geum Seok-jung, Geum Seo-hee, Gyeam-ri, Gyeongseong … /

### 순서와 검토
1. 코드(TDD): 카테고리 일반화 → 허브·IT 목록 → 드라마 목록·글 화면 → 임베드·CTA·JSON-LD → sitemap →
   헤더 드롭다운·푸터.
2. ko 글 4편 + 스틸·썸네일.
3. ko 글 검토(Opus 서브에이전트 — 대본과 대조해 사실·스포 범위·저작권 분량·말투).
4. en·ja·de 번역 + 검토(용어집 일관성).
5. 빌드 산출물 확인: 허브·`tech/`·`drama/` 목록 각 4개 + 드라마 글 16개, 각 글에 iframe·AdSense 태그·
   hreflang·JSON-LD, `sitemap-drama.xml` 에 글 16개, 색인에 `sitemap-drama.xml`, 기존 IT 글 주소가 하나도 안 사라짐(빌드 전후 목록 대조),
   `economy/` 는 아무 데도 없음.
6. **배포(main push)는 사용자가 "올려" 한 뒤에만.**

## 검증 (TDD — 테스트 먼저)

- 기존 `blog-*.test.ts`·`og-metadata`·`products` 테스트가 손대지 않고 통과.
- 새 테스트(예):
  - 드라마 글은 `content/drama` 에서만 읽히고 IT 목록에 안 섞인다.
  - IT 글 slug 가 카테고리 id 와 겹치지 않는다.
  - 글이 없는 카테고리는 허브·헤더·푸터·sitemap 어디에도 안 나온다.
  - 모든 드라마 slug 가 4개 언어에 다 있다.
  - 모든 드라마 글에 11자 `youtube`, `series`, `seriesId`, `image` 가 있고, 본문의 로컬 이미지 파일이 실제로 있다.
  - 본문에 대본 잔재(`@\d+:\d+`, `🔊`, `스틸★`, `(클립`, `(원음)`, `| # |`)가 없다.
  - 글 화면이 iframe(`youtube.com/embed/{id}`)과 두 링크를 그린다(renderToString).
  - `sitemap-drama.xml` 항목의 주소가 `/{lang}/blog/drama/{slug}/` 이고 hreflang 이 붙고, 드라마 글은
    `sitemap-blog.xml` 에 안 섞인다. 색인 = pages + 글이 있는 카테고리마다 하나.
  - 드라마 글 JSON-LD 에 `VideoObject` 가 있다.
